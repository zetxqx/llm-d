# Upstream survey: agentic serving and KV cache control in SGLang and vLLM

Snapshot date: 2026-08-28. Sources: GitHub issues and PRs in [sgl-project/sglang](https://github.com/sgl-project/sglang) and [vllm-project/vllm](https://github.com/vllm-project/vllm), searched for agentic serving, session identity, cache control, retention, and eviction work.

Caveat: statuses and summaries reflect the issue/PR bodies as of the snapshot date. Several items are fast-moving drafts (notably vLLM PR #53423 and SGLang #25760), so re-check before relying on a status here.

TLDR: both engines are converging on the same architecture that llm-d session-control explores: (1) first-class session identity plumbed into the engine, (2) a typed, versioned "KV hint" envelope so a trusted router can express cache intent (pin, prefetch, demote, evict) while the engine keeps ownership of memory, (3) soft retention/priority eviction instead of hard pinning, and (4) session-sticky routing because pure prefix-hash cache-aware routing collapses under widely shared system prompts. The same NVIDIA/Dynamo authors (ishandhanani in SGLang, karen-sy in vLLM) are pushing near-identical KV hint envelope RFCs in both projects.

## SGLang

### Roadmaps and RFCs

- [#27574 [Agentic Inference] Programmatic KV Cache for Agentic Workloads](https://github.com/sgl-project/sglang/issues/27574) (open, high priority, ishandhanani/NVIDIA) - the central RFC. A router above multiple engines passes cache intent hints to SGLang; the engine may clip, defer, or reject them. Phase 1 is session-based KV cache built on #29436 (top-level `session_id`, merged) and #27058 (session-tagged KV blocks, merged). Uses HiCache L3 (Mooncake) as the shared retention and movement substrate.
- [#36224 [RFC] First-Class, Versioned KV Hint Envelope](https://github.com/sgl-project/sglang/issues/36224) (open, 2026-08-24, same author) - the concrete API for #27574: a typed `kv_hints` envelope (`protocol_version`, `message_id`, namespaced `action_type` like `kv.demote`, per-action versioning and idempotency keys). Set by a trusted router after worker selection, never by an untrusted client. Proposed home: `sglang/srt/kv_hints.py`.
- [#21846 [Roadmap] Distributed KVCache System For Agentic Workload](https://github.com/sgl-project/sglang/issues/21846) (open, updated 2026-08-26) - Q3 roadmap: session-aware RadixTree and HiCache (done via [PR #29173](https://github.com/sgl-project/sglang/pull/29173)), a router-to-engine KV orchestrator with `PREFETCH` / `DEMOTE` / `PIN` hints, direct L3 mode for a larger shared pool ([PR #35687](https://github.com/sgl-project/sglang/pull/35687)), and a CPU-only KV cache simulator that replays agentic traces ([#21891](https://github.com/sgl-project/sglang/issues/21891)).
- [#24656 [RFC] Agent-Aware KV Cache Phase 1](https://github.com/sgl-project/sglang/issues/24656) (open, labeled inactive) - proposed an `agent_hints` request field (workflow_id, step DAG, tool duration, TTL, reuse hint) plus an `agent_aware` eviction policy. Its implementation [PR #29199](https://github.com/sgl-project/sglang/pull/29199) was closed without merging; this direction appears to have lost to the #27574 router-hint approach.
- [#30928 [RFC] Position-Independent KV Cache Reuse for Agentic/RAG](https://github.com/sgl-project/sglang/issues/30928) (open) - reuse of identical content at different token offsets. Surveys Irminsul (MLA delta-rotation), MiniPIC (deferred RoPE, IBM/vLLM fork), and COMB. Discussion only, no implementation; notes the radix hash chain is position-coupled today.

### Session identity in the engine (merged)

- [PR #29436 first-class session identity](https://github.com/sgl-project/sglang/pull/29436) (merged 2026-06) - top-level `session_id`, separate from the `session_params.session_id` used by `StreamingSession`.
- [PR #27058 session radix cache](https://github.com/sgl-project/sglang/pull/27058) (merged 2026-06) - tags KV blocks with session identity so KV can be addressed at session level. This is the PR verified in `pr27058-verify/` in this repo.

### Router and session affinity

- [#25760 [Roadmap] Lightweight SessionAware Router for bucket-based PD serving](https://github.com/sgl-project/sglang/issues/25760) (open, updated 2026-08-28, very active) - new sglang-router with per-role bucket dispatch (prefill buckets by `uncached_prefill_tokens`, decode by `estimated_sequence_length`) and a policy fallback chain inside each bucket: sticky (keyed by `routing_key + role + bucket`) -> cache_aware (per-engine approximate prefix tree fed by KV events; global KV-Indexer merged in [PR #33370](https://github.com/sgl-project/sglang/pull/33370)) -> load_based (power-of-two choice scored by `work + lambda * token_usage / (1 - token_usage)`; zmq load reporter merged in [PR #34608](https://github.com/sgl-project/sglang/pull/34608)). Long term it integrates with the agentic KV hint roadmap.
- [#34513 [RFC] Agent-aware session affinity without routing keys](https://github.com/sgl-project/sglang/issues/34513) (open, 2026-08-12) - argues most agent clients cannot pass a routing key, and shows `cache_aware` routing collapses under a widely shared system prompt: on a 29K shared prefix workload it completed 58/110 sessions vs 110/110 sticky, and without stickiness the max SLO-compliant concurrency drops about 4x (C~16 vs C~54-64 on 4x TP=2 Qwen3-32B, DeepSWE traces). Proposes a router policy that infers session identity from request content. Directly overlaps the llm-d session-control problem statement.
- [PR #31170 dp-attention prefix_affinity](https://github.com/sgl-project/sglang/pull/31170) (open) - session affinity across internal DP ranks inside one instance, motivated by Claude-Code-style traffic where a shared system/tools prefix defeats first-N-token hashing ([#26612](https://github.com/sgl-project/sglang/issues/26612)). Includes an overload guard that degrades to load-aware routing.

### Engine-side cache control (eviction, pinning, retention)

- [PR #18941 TTL-based prefix pinning with refresh-on-hit for HiRadixCache](https://github.com/sgl-project/sglang/pull/18941) (merged 2026-03, later reverted via #21884) - hard pins with a pin budget (`SGLANG_HICACHE_MAX_PINNED_RATIO`) and a `/hicache/pin_prefix` endpoint. Reverted because hard pins can wedge the pool; useful as a record of why hard pinning was rejected.
- [PR #27970 soft retention: priority decay via retention_seconds](https://github.com/sgl-project/sglang/pull/27970) (open) - the replacement: requests attach `priority` (clamped to [0, 99], mirroring TRT-LLM `TokenRangeRetentionConfig`) plus `retention_seconds`; effective priority decays to 0 after the retention window, refresh-on-hit extends it. Protection is a bias, not a lock. Evidence on the #27969 agentic-session workload: continuation-turn p95 TTFT 2732ms (LRU) -> 1095ms (2.5x).
- [PR #34012 Agentic-Aware Tail-Optimized LRU (T-LRU) eviction](https://github.com/sgl-project/sglang/pull/34012) (open) - NeurIPS 25 policy ([arXiv:2510.15152](https://arxiv.org/abs/2510.15152)): keep only as much of a conversation cached as its next prefill needs to stay under a TTFT budget, evict the TEL-safe tail first, then fall back to recency. Opt-in via `--radix-eviction-policy tlru`.
- [PR #36409 KVCR as an L3 HiCache backend](https://github.com/sgl-project/sglang/pull/36409) (open, updated 2026-08-28) - hint-driven cross-instance KV reuse through a shared L3 storage backend.
- [PR #31723 anti-starvation aging for lpm schedule policy](https://github.com/sgl-project/sglang/pull/31723) and [PR #31710 runtime schedule_policy switching](https://github.com/sgl-project/sglang/pull/31710) (both open) - smaller scheduler-side knobs relevant to mixed agentic traffic.

### Bugs worth knowing

- [#36877 Anthropic /v1/messages: rolling cache_control breakpoints invalidate prefix cache](https://github.com/sgl-project/sglang/issues/36877) (open, filed 2026-08-28) - Claude Code moves its ephemeral `cache_control` breakpoint forward every turn; SGLang's Anthropic layer segments tokenization at breakpoints, so a moved breakpoint re-tokenizes the boundary and invalidates the whole prefix before it, causing a full 60K+ token re-prefill every 2-3 turns (100% <-> ~0% alternating hit pattern). Stripping `cache_control` at the gateway raised weighted hit rate 84.3% -> 88.5% and produced 27 straight turns at 99-100%. Directly relevant to any Claude-Code-trace benchmark against an Anthropic-compatible endpoint.
- [#35129 HiCache long agentic sessions get 0 cached tokens every turn](https://github.com/sgl-project/sglang/issues/35129) (open) - DSv4 + DSPARK + HiCache: long sessions report `#cached-token: 0` despite a stable 50%+ prefix, while short requests hit ~98%.
- [#32459 EAGLE speculative decoding defeats radix prefix reuse for multi-turn traffic](https://github.com/sgl-project/sglang/issues/32459) (open) - silent 97% -> 40-53% reuse collapse; spec decode and prefix reuse interact badly on multi-turn.

### Benchmarks

- [PR #27969 serving-boundary suite](https://github.com/sgl-project/sglang/pull/27969) (open) - mixed prefill/decode, repeated-prefix, and agentic-session workloads; used as the evidence base for #27970.
- Existing `bench_serving` support for `--dataset-name agentic-trace`, used by #34513 for its shared-prefix sweep.

## vLLM

### RFCs (hint envelope and session identity)

- [#51428 [RFC] Programmatic Session-Aware KV Cache Management](https://github.com/vllm-project/vllm/issues/51428) (open, 2026-08-07, karen-sy/NVIDIA) - the vLLM counterpart of SGLang #27574: a narrow, router-initiated "KvHint" surface where the orchestrator (explicitly Dynamo) expresses policy intent and vLLM resolves it against exact cache state, free to clip, defer, or reject.
- [#53421 [RFC] First-Class, Orchestrator-Agnostic KV Hint Envelope](https://github.com/vllm-project/vllm/issues/53421) (open, 2026-08-23, same author, companion implementation [PR #53423](https://github.com/vllm-project/vllm/pull/53423)) - the vLLM counterpart of SGLang #36224, with an essentially identical envelope: `KvHintsEnvelope` / `KvHintAction` in `vllm/v1/kv_hints/`, typed and versioned, opaque per-action payloads, flowing `router -> EngineCoreRequest.kv_hints -> Request.kv_hints -> scheduler-visible metadata`. Replaces today's untyped plumbing through `SamplingParams.extra_args` and `kv_transfer_params` (e.g. [Dynamo PR #13134](https://github.com/ai-dynamo/dynamo/pull/13134)).
- [#48049 [RFC] First-class session id for conversation aware routing](https://github.com/vllm-project/vllm/issues/48049) (open, karen-sy) - adds typed `request.session_id` instead of overloading `request_id` or hiding identity in `extra_args`. Explicitly for Dynamo integration; cites SGLang PR #29436 as the reference. Implementation in [PR #48048](https://github.com/vllm-project/vllm/pull/48048); current workaround is [PR #46547](https://github.com/vllm-project/vllm/pull/46547) (X-Session-ID header -> `extra_args` -> Mooncake metadata).
- [#48501 [RFC] Session-centric KV-cache orchestration over typed session identity](https://github.com/vllm-project/vllm/issues/48501) (open, vMaroon/IBM, llm-d-affiliated) - builds on #48049: the control plane (named: llm-d, Dynamo) becomes the cluster's memory map while the engine stays policy-unaware. Asks for two engine capabilities, both intent-free: KV events reported in session coordinates (which stored blocks belong to which session), and directives addressable in session coordinates (retention, offload, move, prefetch). Adds a second continuation/position coordinate because `session_id` alone cannot locate a position within a lineage.
- [#52113 [RFC] Session-Aware KV Cache Hints for Agentic Workloads](https://github.com/vllm-project/vllm/issues/52113) (open, 2026-08-13, FermatGo) - application-supplied `agent_hint` metadata: session identity, short retention TTL, explicit release/prefetch operations for tool-call gaps, parent/child agent branches, and completed branches. Closer in spirit to SGLang's #24656 (app hints) than to the router-envelope RFCs.
- [#52567 [RFC] First-class agentic inference support in vLLM](https://github.com/vllm-project/vllm/issues/52567) (open, 2026-08-17) - how vLLM should integrate with the [vllm-project/agentic-api](https://github.com/vllm-project/agentic-api) Rust runtime (stateful continuation, tool loops, MCP, Responses/Messages compatibility; MVP already supports Codex and Claude Code). Serving-surface question rather than KV mechanics, but frames agentic workloads as a first-class vLLM target and explicitly mentions llm-d.
- [#37003 [RFC] Context-Aware KV-Cache Retention API (Prioritized Evictions)](https://github.com/vllm-project/vllm/issues/37003) (open since 2026-03, vMaroon, tracked in an llm-d doc) - token-range retention directives with per-range eviction priorities. Motivation data: 90%+ of agent-turn tokens are verbatim prefix reuse, 40-60% of session wall time is paused on tool calls, and LRU evicts those blocks under concurrent load. Cites Continuum, KVFlow, MARCONI, and Alibaba trace studies as evidence that LRU loses badly.
- [#44775 Explicit cache breakpoints and cache usage accounting in OpenAI-compatible API](https://github.com/vllm-project/vllm/issues/44775) (closed 2026-06) - proposed Anthropic-style `cache_control` parsing and `cache_read/creation_input_tokens` accounting; closed, with the retention API family carrying the surviving ideas.

### Engine-side implementations (open PRs)

- [PR #38514 Context-Aware KV-Cache Retention API](https://github.com/vllm-project/vllm/pull/38514) (open since 2026-03, active) - implements #37003: token-range retention directives on requests, a two-structure evictor in `block_pool.py` (LRU + priority min-heap with lazy TTL expiry), `priority` / `priority_expiry` / `priority_scope` on `KVCacheBlock`, zero-overhead fast path when no directives are present. E2E benchmarked with inference-perf agentic synthetic workload and a `ContinuumPolicy`.
- [PR #47837 Priority-aware KV cache eviction for priority scheduling](https://github.com/vllm-project/vllm/pull/47837) (open) - ties eviction order to request priority.
- [PR #51384 Bounded session-affinity scheduler](https://github.com/vllm-project/vllm/pull/51384) (open) - opt-in V1 scheduler that promotes at most one cache-warm continuation of a recently active typed `session_id` within a bounded FCFS window; requires an actual local prefix-cache hit and a head-wait deadline so FCFS fairness is preserved.
- [PR #50422 [kv_offload] Session Aware Eviction (SAE) policy](https://github.com/vllm-project/vllm/pull/50422) (open) - CPU-offload tier eviction that treats a session's block chain as a unit and evicts session-worst-first, tail-first, so shared prefixes outlive their suffixes (mid-chain evictions force recompute of everything after them).
- [PR #51381 Echo session_id on GPU BlockStored KV events](https://github.com/vllm-project/vllm/pull/51381) (open, draft) - implements the visibility half of #48501 for GPU events; lets an external indexer map KV lifecycle to sessions without recomputing engine hashes. Directly relevant to the llm-d EPP KV-events indexer.
- [PR #48288 Internal session id for offloading](https://github.com/vllm-project/vllm/pull/48288) (open) - propagates typed session identity into offloading and Mooncake metadata.
- [PR #43372 AsyncLLM.truncate_session](https://github.com/vllm-project/vllm/pull/43372) (open) - per-session KV truncation API for live streaming sessions (drop a stale suffix without tearing the session down), plus a hook for future StreamingLLM-style middle-range eviction. Related bugfix stream: #53156, #52806, #53876 (bounded-memory streaming sessions with retention and in-place KV eviction), #43374 (experimental session KV eviction with attention sinks).

## Cross-engine observations

1. The KV hint envelope RFCs are twins: SGLang #36224 and vLLM #53421 propose byte-compatible-looking envelopes (`protocol_version`, `message_id`, `action_id`, `action_type`, `action_version`, opaque payload), driven by NVIDIA/Dynamo people in both projects. A de facto cross-engine router-to-engine KV protocol is forming; llm-d should track it (see also SGLang #36224's framing that hints are set by a trusted router after worker selection, which matches the EPP position in llm-d).
2. Session identity landed first in SGLang (PRs #29436, #27058 merged in June) and vLLM is following the same design (#48049/#48048), citing the SGLang PRs as reference.
3. Hard pinning is out, soft retention is in, in both engines: SGLang merged then reverted TTL pinning (#18941) and now pursues priority decay (#27970); vLLM's retention API (#37003/#38514) was priority-biased eviction from the start. Both cite TRT-LLM's `TokenRangeRetentionConfig` and the Continuum paper.
4. Routing conclusion in both ecosystems matches the llm-d session-control thesis: prefix-hash cache-aware routing collapses under widely shared system prompts, and session stickiness (with a load-aware escape hatch) is required for agentic traffic (SGLang #34513, #25760; vLLM #51384 at the scheduler level).
5. Anthropic-endpoint cache_control handling is an active failure mode for Claude Code traffic on both engines (SGLang #36877, vLLM #48874, closed vLLM #44775). Relevant to any benchmark that replays Claude Code traces through an Anthropic-compatible endpoint: consider stripping or normalizing `cache_control` at the gateway.
